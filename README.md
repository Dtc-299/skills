# DTC Skills：对话浓缩与任务交接

把长聊天整理成可追溯的 Markdown 交接包，让新窗口带着关键数据、决策和任务断点继续工作。

本仓库包含两个配套的 Codex skills：

| Skill | 作用 | 默认范围 |
| --- | --- | --- |
| [`dtc1`](skills/dtc1/SKILL.md) | 浓缩历史、整理事实和任务、保存交接包 | 当前这一个聊天的全部可访问历史问答 |
| [`dtc2`](skills/dtc2/SKILL.md) | 读取交接包，校验范围和实际状态，恢复任务 | 用户指定的交接；只有一份时可自动读取 |

支持只处理一个聊天，也支持明确选择多个聊天后合并。**不会因为聊天属于同一个项目、共用同一个目录，就默认把它们全部合并。**

## 使用示例

### 1. 浓缩当前这个聊天

在旧窗口输入：

```text
$dtc1
```

处理范围是这个聊天从第一条到当前的全部可访问历史问答。`dtc1` 会记录具体读取范围，保留关键数字、单位、用户约束、方案理由、失败经验、文件索引和未完成任务。

### 2. 选择多个聊天合并

```text
$dtc1 合并“主任务”和“补充任务”两个聊天的全部历史，其他聊天不加入。
```

Codex 将标题解析为真实聊天 ID，只处理明确选中的集合。重名或选择不明确时，会先确认范围；读取不到某个聊天或早期历史时，必须列出缺口。

只有明确要求“项目内全部聊天”时，才枚举并选择整个项目。

### 3. 新窗口接手

优先复制 `dtc1` 完成后给出的、包含交接快照绝对路径的指令：

```text
$dtc2 <交接快照的绝对路径>
```

也可以按集合名称指定：

```text
$dtc2 恢复“主任务 + 补充任务”的交接，继续上次未完成的任务。
```

当前目录只有一份已发布交接时，可以直接输入 `$dtc2`。存在多份时，会依据用户指定的名称、来源或路径选择，不能擅自猜测最近一份。

## 安装

需要支持本地 skills 的 Codex 环境，以及 Python 3.10+。DTC 脚本只使用 Python 标准库，不需要额外 Python 包、API key 或记忆后台服务。Git 用于可选的工作区状态核对。

### Windows PowerShell

```powershell
git clone https://github.com/Dtc-299/skills.git
cd skills
.\install.ps1
```

安装程序将 `skills/dtc1`、`skills/dtc2` 复制到 `$CODEX_HOME/skills`；未设置 `CODEX_HOME` 时，使用用户目录下的 `.codex/skills`，然后核对文件 SHA-256。

升级已安装版本：

```powershell
.\install.ps1 -Update
```

升级前会备份被替换的旧文件，并输出备份位置。可通过 `-TargetRoot` 指定自己的 skills 目录。安装程序不会修改模型配置或项目代码。

### 手动安装

将仓库中的以下两个完整目录复制到自己的 Codex skills 目录：

```text
skills/dtc1/
skills/dtc2/
```

覆盖已有版本前先保留原目录。当前自动安装与测试在 Windows 环境验证；其他系统的安装方式需自行核对。

安装后在新聊天中调用 `$dtc1` 或 `$dtc2`。如果当前会话尚未发现新 skill，可以重新开启聊天；仍未出现时再重启应用。

## 怎样尽量保留关键内容

- **三层资料**：入口摘要、结构化事实与任务台账、可回查的来源归档。
- **精确数据**：数值保留字符串、单位、时间和原始／计算／估算类别；计算值记录公式与输入。
- **来源可追溯**：重要结论有来源文件和定位信息，区分用户确认、实际观察、推断和建议。
- **决策可接续**：保留选择理由、被替代的方案、失败原因和验收依据。
- **范围明确**：按聊天 ID 选择，多个集合各自保存，不互相覆盖。
- **发布前检查**：未读来源、无效引用、丢失旧台账 ID、没有验证依据的完成状态会阻止发布。
- **版本与完整性**：保留旧快照，使用文件哈希、父版本检查、排他锁和原子入口更新。
- **恢复核对**：检查所选聊天集合、关键理解问题，以及 Git 分支、HEAD 和工作区状态是否变化。

## 交接文件保存在哪里

交接资料写在所选存储目录的 `.dtc` 下，**不会自动上传到 GitHub**：

```text
.dtc/
└─ handoffs/
   └─ <单聊或多聊集合标识>/
      ├─ CURRENT.json
      └─ snapshots/
         └─ <版本>/
            ├─ START_HERE.md
            ├─ MEMORY.md
            ├─ ledger.json
            ├─ review.json
            ├─ manifest.json
            └─ sources/
```

如有需要，Codex 还会写入按主题组织的资料和任务相关证据。迁移时带上完整的所需集合目录，不能只复制入口摘要后期待所有来源都能回查。

## 能力边界

这是一套 **Codex 工作流程 + 确定性辅助脚本**。脚本负责采集、引用与结构检查、封存和恢复验证；理解对话与撰写总结由 Codex 完成。

- 本地采集支持当前适配的 Codex JSONL 日志。按标题读取其他聊天，需要运行环境提供相应聊天工具，或能够找到这些聊天的本地记录。
- 没有权限访问、已经丢失或只有截断摘要的历史，不能声称完整读取。
- 图片、音视频、二进制附件和工具输出中的关键证据，需要另行读取并记录；默认文本导出不等于已经理解全部附件。
- 排除隐式推理、系统／开发者指令和工具原始输出；常见凭据会脱敏，但自动脱敏不是通用的敏感数据保证。
- 哈希通过只能说明封存文件未变化，结构检查通过不能证明语义没有遗漏。
- **不保证绝对零遗漏，也不保证不同窗口或不同模型的能力完全一致。** 不会为恢复任务自动更换模型或调整推理设置。

## 测试

在仓库根目录执行：

```powershell
python -X utf8 -B tests/test_dtc.py
```

当前包含 25 项合成数据测试，覆盖单聊默认、多聊选择、排除未选聊天、目录切换、精确数值、引用、文件修改、并发发布、台账留存及独立恢复。测试不读取真实聊天。

详细记录见[测试报告](docs/测试报告.md)，日常操作见[中文使用说明](docs/使用说明.md)。这些测试不等同于独立模型的跨窗口语义评测。
