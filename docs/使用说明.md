# DTC v1.1 · 单聊浓缩与指定多聊合并

安装后，在旧对话输入 **`$dtc1`**，默认只浓缩当前这一个聊天从第一条到当前的全部可访问问答；输入 **`$dtc1 合并“主任务”和“补充任务”的全部历史`**，就只合并这两个聊天。新窗口用 **`$dtc2 <交接快照路径>`** 恢复指定交接。也支持识别 dtc1/dtc2，但显式 `$` 更明确。暂未发现 skill 时重新开对话；仍未发现再重启应用。

两个入口分别负责保存与恢复。资料写在存储目录的 `.dtc/handoffs/<集合标识>/`，单聊和每个明确选定的多聊集合各自有版本、CURRENT 和来源清单，互不覆盖。skill 默认安装在 `~/.codex/skills/dtc1`、`~/.codex/skills/dtc2`。无需 API key、联网服务或额外 Python 包；脚本需要 Python 3.10+。

## 日常用法

```text
旧窗口：$dtc1
新窗口：$dtc2
```

```text
$dtc1 只浓缩当前这个聊天的全部历史，重点保留接口、参数、失败原因和未完成工作。
$dtc1 合并“主任务”和“补充任务”两个聊天的全部历史，其他聊天不加入。
$dtc2 恢复“主任务 + 补充任务”的交接，继续上次未完成的任务。
```

“全部历史”指所选每个聊天内部的全部轮次，不代表默认整个项目。只有你明确要求项目所有聊天时，才枚举并选择整个项目。选择按真实聊天 ID，不按共用目录；聊天内部换过工作目录，早期问答也应保留。当前 ID 不明时不能猜，点名聊天重名时简短确认。云端、缺失历史或附件的限制必须记录。skill 不会自动新建聊天，也不会切换模型或调整推理档位。

新窗口只输入 `$dtc2` 时，当前目录只有一份已发布交接才自动恢复；有多份则根据你指定的名字/来源选择或询问，不能擅自选最近一份。每次 dtc1 完成都会给一条包含快照路径的恢复指令，直接复制到新窗口即可。

保存时，Codex 枚举来源、分块读取、提取事实、反查证据，再封存版本。恢复时，先核验哈希，读取任务入口和相关事实，检查实际工作区状态，然后继续明确的未完成任务。脚本不能自行理解或总结对话；它配合 skill 中的 Codex 工作流程执行。

## 保真机制

- 原文归档与摘要分开：对话中的可见文本分块保留，不用摘要取代所有证据；源日志只读，不被清除。
- 数值保留字符串、单位、时点与原始/计算/估算类别；决策附理由、来源与替代关系。
- 稳定台账 ID：新版本不能静默删除旧事实和未完成任务。
- 未读来源、缺少引用、没有验证依据的完成状态会阻止发布。
- 多版本和原子入口：中断、并发或校验失败不会覆盖上一有效版本。
- 新窗口核对 Git HEAD/分支/工作区文件内容指纹，检测旧测试结论是否需要重新核实。
- 理解核对题用于检查目标、关键约束、数据和下一步是否能正确恢复。

归档只保存用户/助手可见文本，排除隐式推理、系统指令和工具原始输出；工具输出中的关键证据由 Codex 按需另存 evidence。图片等非文本内容需要另行读取并记录来源。常见凭据会脱敏，但自动规则并非完整的敏感数据扫描器；封存前还需检查。

**不能承诺绝对零遗漏、“不降智”或模型等价。** 可承诺的工程行为是：不伪称读过不可读的历史；明确标出缺口；保留可回查依据；机械检查引用与完整性。语义总结仍需要模型正确执行，模型/推理设置和窗口容量也会影响效果。

## 维护和迁移

已发布版本不要手工编辑；修订通过 `$dtc1` 新建快照。迁移时带上完整 `.dtc/handoffs/<所需集合>/`，包括 CURRENT、snapshots 和来源证据；用显式快照路径恢复并核对旧路径映射。只复制 START_HERE.md 不提供完整回查。旧版或手工交接先检查来源清单和实际读取范围：合并范围符合用户要求，不等于历史已完整读取；不能直接断言旧内容全错。

备份包安装方式：PowerShell 运行本目录 `install.ps1`；升级用 `install.ps1 -Update`。它只复制 dtc1/dtc2 并自查哈希；升级前将被替换文件备份到 skills 同级的 skill-backups 目录，不删除自定义文件。`-TargetRoot` 可指定 Codex skills 目录。不会改 AGENTS.md、模型配置或项目代码。
