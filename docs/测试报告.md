# DTC v1.1 验证记录

初版创建于2026-10-17，本次更新为 v1.1。Python：Codex 随附 Python；测试仅用合成对话和隔离项目，未浓缩或导出用户真实聊天。

25 项自动测试全部通过，覆盖：

1. 坏引用与没有验收证据的 done 状态被拒绝。
2. 两个并发草稿发布时，后发布者不能覆盖新 CURRENT。
3. 常见凭据脱敏不会改变普通数值和单位。
4. Git 中同一路径、同一 dirty 状态的内容变化也能被检测。
5. dtc2 自带脚本可独立验证并恢复 next_task_id；额外未封存文件会被发现。
6. event 回退与 response 消息去重，同时保留真实的重复提问。
7. L2 引用不能误命中 L20。
8. 后续版本不能静默删除旧台账 ID。
9. 未处理的图片附件不能声称已覆盖全部可访问来源。
10. 未读来源与被转成浮点数的精确数值会阻止发布。
11. 大于 65000 字符的消息分块后保留结尾；相似目录前缀不导致串档。
12. 已有发布锁被保留，不覆盖其他写入者。
13. 已选聊天的损坏记录登记为缺口，不因此截掉后续可读取历史。
14. manifest 被修改时 CURRENT 哈希核验失败。
15. 同一已选聊天的正常、归档及切换目录前后的完整历史均保留。
16. 正常发布与封存后修改检测。
17. analysis、工具原始输出排除，用户可见消息保留。
18. 两份 skill 的 frontmatter、UI YAML 使用的标量子集、长度、调用入口和相对引用检查。
19. 两个独立安装目录中的脚本内容一致。
20. 默认仅当前聊天，同目录其他聊天不加入。
21. 当前聊天 ID 不明时失败，不回退为整个项目。
22. 显式合并两个聊天，包含双方早期和最新消息，排除第三个聊天；选择顺序不改变集合身份。
23. 单聊与多聊交接互不覆盖；多份恢复时禁止自动猜测，能列出已发布集合。
24. 来源属于未选聊天时拒绝发布。
25. 所选聊天找不到时记录缺口，不能声称全部已读。

另外：安装脚本已在工作区的隔离目标完成复制和 10 个文件的 SHA-256 核对。

命令：

```powershell
& '<可用的Python路径>' -X utf8 -B '.\tests\test_dtc.py'
```

内置 skill-creator 的 quick_validate.py 已尝试运行，但当前 Python 缺少它所需的 PyYAML，未能完成该官方辅助检查；上面的包格式测试针对实际使用的简单 YAML 子集进行了独立校验。DTC 运行本身不依赖 PyYAML。

测试证明的是确定性采集与完整性机制。没有独立模型跨窗口语义评测，不能据此保证所有历史均可访问、总结零遗漏、或不同模型能力完全相同。执行 skill 时仍需逐项反查原文和落实恢复检查。
